## M1.1 Bounded UTF-8 File Opening

The desktop opens one regular file supplied as `--open PATH`. File I/O reads at most 4 MiB plus one byte to detect overflow, even if a file grows after metadata is checked. It rejects unsupported BOMs and invalid UTF-8. Valid bytes, including LF and CRLF, enter the existing core Document unchanged. The view and plugin host share that document. The M1.1 toolbar displayed the filename and a notice that saving was unavailable.

The read uses a read-only handle before the window is created. Edits and plugin transactions affect the in-memory document. At M1.1, close confirmation protected sessions after any edit, including when undo returned to the initial text. M1.2 replaced that rule with an exact saved-content baseline.

2. Ctrl+Shift+S created `new 中文.rs` at an absolute path. Save As to `overwrite 中文.rs` required a second confirmation before writing. Both paths received the same bytes as the saved source, and the association followed each successful save.
3. Closing with an unsaved edit showed Save, Discard, and Cancel. Cancel returned to the edited document. 5. In a scratch document, physical Pinyin keys opened a native candidate popup near the caret. Ctrl+S during candidate selection left the popup and the zero-byte document unchanged. The toolbar Save then created the destination, cleared the star, and wrote exactly `E4 BD A0` in UTF-8. The clean window closed normally.

## M1.3 Multiple Documents and Tabs

**Implemented; scoped checks recorded on 2026-11-04/05 (Asia/Shanghai).** Full M1 acceptance is still pending. These observations were collected from the M1.3 development tree based on `867db8a5c3c43b81417b6b45863852a0ce8493bb`; the observed executable hashes are recorded below. Committing the implementation does not constitute full M1 acceptance. Windows 11 Pro build 26300, Rust 1.99.1, x86_64-pc-windows-msvc, debug profile. No dependency or wire ABI changes.

Each tab owns its core document/saved snapshot, view, file association/disk baseline, save worker, status, and close state. Every worker completion carries DocumentId. Unknown/closed IDs are ignored; IDs are never reused. Saving another tab does not change the active plugin target. A requested tab close retains its worker until completion and rechecks intervening edits before closing. See the [ownership and lifetime decisions](../ARCHITECTURE.md#m13-tabs-and-active-document-routing).

### Automated checks

| Command | Result |
|---|---|
| `cargo xtask verify` | Passed on Windows: fmt, clippy with warnings denied, 80 Rust tests, staged real text-tools cdylib, and real-plugin/no-plugin startup |
| `python -B -m unittest discover -s tests/perf -p "test_*.py"` | 4 passed |
| `git diff --check` | Passed |

Desktop tests hold real write completions pending with test-only gates, switch active tabs, and release results in reverse order. They verify independent paths/disk baselines/saved contents, newer edits staying dirty, undo back to each save point, close waiting on an inactive saving tab, Save As inspection following its owner, and failed saves preserving originals and aborting window close. An external-change failure retains only the affected tab's prior baselines. A frame-level test makes the worker result ready before incoming text and verifies that the text is processed before closing can remove its owner. Foreign snapshots and the 32-tab bound are checked.

The real-library integration test switches between two documents without reloading text-tools, verifies independent selection/history/modified state, and confirms that the host releases a closed document and rejects invocation with no active document. Callback tests reject an old tab's replacement when both tabs have the same revision. Synthetic view/application tests cancel preedit across a tab switch, reject delayed commits in both views, and permit a fresh session to commit once. Existing version/size/capability/thread/panic/lifecycle and subprocess-abort tests remain enabled.

These gates hold UI-side completion delivery pending; they do not simulate a stalled disk, power loss, or arbitrary publication timing. No production delay switch was introduced.

### Windows native observations

The native window reported 125% scale. Only isolated files under ignored `target/m1-tabs-tests` were written. The tracked fixture was not edited. The plugin-enabled observations used executable SHA-256 `08a06273dc8e11564521696e8dc37a30b4dadec191cd7d29bd728ebcaeb6049a`. After moving completion handling behind frame input and adding the frame/IME regressions, the no-plugin run used `a70455aa115406d50d647432cfe24b318c1d29ccc2fb204e806f79c0ab51887a`. A subsequent source cleanup releases the startup document's temporary Rc before the GUI run; these hashes identify the observed binaries rather than asserting that all observations came from the same build.

```powershell
cargo xtask verify
target/debug/rusteditor-desktop.exe --open target/m1-tabs-tests/a.txt --open target/m1-tabs-tests/b.txt
target/debug/rusteditor-desktop.exe --no-plugins --open target/m1-tabs-tests/a.txt --open target/m1-tabs-tests/b.txt
```

1. Initial files contained `alpha 你好 straße🙂 é` and `beta 世界 straße🙂 é`, without a trailing newline. Selecting all in A and invoking Ctrl+Shift+U produced `ALPHA 你好 STRASSE🙂 É` and a modified star. Ctrl+Tab displayed B unchanged. Selecting B and clicking **Run command** uppercased B; Ctrl+Z restored B and removed only its star. Ctrl+Shift+Tab restored A's uppercase contents and full selection. Ctrl+S saved A and removed its star.
2. Ctrl+N created Untitled 3. Literal `ni` remained a two-byte unsaved edit in that session. With B active, clicking Untitled 3's close button named Untitled 3 in the prompt. Cancel kept all three tabs and B active. Repeating the close and choosing Save opened a Save As dialog for Untitled 3. Saving `scratch.txt` closed only that tab; B remained active. Reading the three files and comparing their complete strings confirmed uppercase A, unchanged B, and exactly `ni` in scratch.
3. Alt+F4 closed the two remaining clean tabs and the process. With `--no-plugins`, the Extensions panel showed zero plugins. Ctrl+Tab selected B; Ctrl+W closed B and then A, leaving the empty-workspace UI. Ctrl+N created Untitled 3, demonstrating that closed IDs were not reused.
4. Physical `x` opened a native Chinese candidate popup near Untitled 3's caret while its document remained zero bytes. Space committed `想` (3 bytes, revision 2). After creating Untitled 4 and returning to Untitled 3, physical `n` reopened candidates while the source stayed at 3 bytes. Clicking Untitled 4 removed candidates and showed a zero-byte clean destination. Returning to Untitled 3 showed only `想`, with unchanged revision. In Untitled 4, a fresh physical `n` plus Space committed only `你` (3 bytes, revision 2); one Ctrl+Z returned it to zero bytes and removed its star. The input-method vendor was not independently identified in this run; this is a scoped native candidate/cancellation observation, not a complete named-IME matrix.

The first plugin-enabled window captures showed a blank client area until a click refreshed the editor; the later no-plugin launch displayed immediately. Startup latency and that initial capture behavior were not investigated or accepted by this tab-focused check.

**Remaining validation:** Windows 10; native 100%/150%/200% DPI; the full named-IME/event-order/clipboard matrix after the tab layout change; Linux/macOS GUI and fresh cross-platform CI for this patch. The save/switch/close completion races are reproducible automated tests, not a claim that a naturally slow native save was observed. M1.4 and M1.5 remain open.
