## M1.1 Bounded UTF-8 File Opening

The desktop opens one regular file supplied as `--open PATH`. File I/O reads at most 4 MiB plus one byte to detect overflow, even if a file grows after metadata is checked. It rejects unsupported BOMs and invalid UTF-8. Valid bytes, including LF and CRLF, enter the existing core Document unchanged. The view and plugin host share that document. The M1.1 toolbar displayed the filename and a notice that saving was unavailable.

The read uses a read-only handle before the window is created. Edits and plugin transactions affect the in-memory document. At M1.1, close confirmation protected sessions after any edit, including when undo returned to the initial text. M1.2 replaced that rule with an exact saved-content baseline.

## M1.3 Multiple Documents and Tabs

**Implemented; scoped checks recorded on 2026-11-04/05 (Asia/Shanghai).** Full M1 acceptance is still pending. These observations were collected from the M1.3 development tree based on `867db8a5c3c43b81417b6b45863852a0ce8493bb`; the observed executable hashes are recorded below. Committing the implementation does not constitute full M1 acceptance. Windows 11 Pro build 26300, Rust 1.99.1, x86_64-pc-windows-msvc, debug profile. No dependency or wire ABI changes.

Each tab owns its core document/saved snapshot, view, file association/disk baseline, save worker, status, and close state. Every worker completion carries DocumentId. Unknown/closed IDs are ignored; IDs are never reused. Saving another tab does not change the active plugin target. A requested tab close retains its worker until completion and rechecks intervening edits before closing. See the [ownership and lifetime decisions](../ARCHITECTURE.md#m13-tabs-and-active-document-routing).

### Automated checks

| Command | Result |
|---|---|
| `cargo xtask verify` | Passed on Windows: fmt, clippy with warnings denied, 80 Rust tests, staged real text-tools cdylib, and real-plugin/no-plugin startup |
| `python -B -m unittest discover -s tests/perf -p "test_*.py"` | 4 passed |
| `git diff --check` | Passed |

Desktop tests hold real write completions pending with test-only gates, switch active tabs, and release results in reverse order. They verify independent paths/disk baselines/saved contents, newer edits staying dirty, undo back to each save point, close waiting on an inactive saving tab, Save As inspection following its owner, and failed saves preserving originals and aborting window close. An external-change failure retains only the affected tab's prior baselines. A frame-level test makes the worker result ready before incoming text and verifies that the text is processed before closing can remove its owner. Foreign snapshots and the 32-tab bound are checked.

The real-library integration test switches between two documents without reloading text-tools, verifies independent selection/history/modified state, and confirms that the host releases a closed document and rejects invocation with no active document. Callback tests reject an old tab's replacement when both tabs have the same revision. Synthetic view/application tests cancel preedit across a tab switch, reject delayed commits in both views, and permit a fresh session to commit once. Existing version/size/capability/thread/panic/lifecycle and subprocess-abort tests remain enabled.

These gates hold UI-side completion delivery pending; they do not simulate a stalled disk, power loss, or arbitrary publication timing. No production delay switch was introduced.

## M1.4 Everyday Editing UI

**Implemented; scoped checks recorded on 2026-11-05 (Asia/Shanghai). Full M1 acceptance remains pending.** Development started from main at `be0c1fe83f9270aa79ea5b8155c501c68ebdf7e7` in a clean worktree, on branch `codex/m1-everyday-ui`. Results below identify the M1.4 working tree and observed executable hashes, not a claim that a new commit or CI run exists. Windows 11 Pro build 26300, x86_64-pc-windows-msvc, Rust/Cargo 1.99.1, debug profile. Dependencies, Cargo.lock, core transactions and the plugin wire ABI are unchanged.

The core remains the only editable document. The view adds a gutter and cached read-only status metrics. File/Edit menus and toolbar buttons share availability rules; the focused editor retains ordered text/undo events. One background reader opens strict UTF-8 without BOM as a fresh tab, with the existing 4 MiB cap and a baseline captured from the reading handle. Pending reads reserve a tab slot; cancellation discards the result while retaining that slot until the read finishes. See the [implementation and cancellation decisions](../ARCHITECTURE.md#m14-everyday-editing-ui).
