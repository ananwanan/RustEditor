## M1.1 Bounded UTF-8 File Opening

The desktop opens one regular file supplied as `--open PATH`. File I/O reads at most 4 MiB plus one byte to detect overflow, even if a file grows after metadata is checked. It rejects unsupported BOMs and invalid UTF-8. Valid bytes, including LF and CRLF, enter the existing core Document unchanged. The view and plugin host share that document. The M1.1 toolbar displayed the filename and a notice that saving was unavailable.

The read uses a read-only handle before the window is created. Edits and plugin transactions affect the in-memory document. At M1.1, close confirmation protected sessions after any edit, including when undo returned to the initial text. M1.2 replaced that rule with an exact saved-content baseline.

## M1.2 Safe Save and Modified State

**Scoped acceptance passed on 2026-11-04.** Windows 11 Pro build 26300 on x86_64 MSVC used Rust 1.99.1. Linux used Ubuntu 24.04 under WSL2 on ext4 with Rust 1.98.1. The pre-change Windows baseline at `0fc8113` passed `cargo xtask verify` with 53 Rust tests and both native-library startup smoke checks.

### Automated checks

| Command | Result |
|---|---|
| `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets --locked -- -D warnings` | Passed on Windows and via `xtask verify` on Linux |
| `cargo test -p rusteditor-editor-core --locked` | 6 passed on Windows. Exact saved content, selection, undo/redo across the save point, and document identity are covered |
| `cargo test -p rusteditor-file-io --locked` | 19 passed on Windows and 19 in the Linux workspace run |
| `cargo test --workspace --locked` | 66 passed on Windows and 67 via `xtask verify` on Linux. The desktop worker test confirms that newer edits stay dirty and a failed save leaves the baseline intact |
| `python -B -m unittest discover -s tests/perf -p "test_*.py"` | 4 passed per platform, using `python3` on Linux |
| `cargo xtask verify` | Passed on both platforms, including the staged native plugin, plugin dirty/undo/redo assertions, and no-plugin startup |
| `cargo xtask stage` and `git diff --check` | Passed on Windows |

File I/O tests verify exact empty, ASCII, Unicode, LF, and CRLF bytes, a Unicode path with spaces, no-clobber creation, explicit existing-target inspection, and external edits, deletion, and replacement. Fault injection covers denied directory or staging creation, temporary name failure, partial write with simulated disk exhaustion, flush, sync, and commit failures. A subprocess exits after staging and before publication and leaves the original intact. Windows tests exercise a real file handle that denies delete sharing, a protected DACL, named-stream preservation, and the partial-failure restoration logic with and without a destination collision. Linux tests exercise a real advisory lock, a directory without write permission, preserved mode bits, rejected extended attributes, and symlink rejection.

### Windows GUI checks

The tests used a native 125% window and only wrote to isolated files under `target/m1-save-tests`. The tracked fixture retained SHA-256 `634b8b431d5f4553ebe4efa057ba7f26318efe383f392c580597ae2b85cdd827`. The final tested debug executable had SHA-256 `7a1b64548d03d08f40a2839024ede57379bd4d26347aafeb0fdcaa9550fea807`.

```powershell
cargo xtask stage
New-Item -ItemType Directory -Force target/m1-save-tests | Out-Null
Copy-Item tests/fixtures/probe.rs target/m1-save-tests/probe.rs
Copy-Item tests/fixtures/probe.rs 'target/m1-save-tests/overwrite 中文.rs'
cargo run --locked -p rusteditor-desktop -- --no-plugins --open '.\target\m1-save-tests\probe.rs'
cargo run --locked -p rusteditor-desktop -- --open '.\target\m1-save-tests\new 中文.rs'
cargo run --locked -p rusteditor-desktop -- --no-plugins --empty
```

1. With plugins disabled, literal Chinese, emoji, and a combining sequence marked the opened copy modified. Ctrl+Z removed the star, Ctrl+Y restored it, and Ctrl+S wrote the exact contents and cleared the star.
2. Ctrl+Shift+S created `new 中文.rs` at an absolute path. Save As to `overwrite 中文.rs` required a second confirmation before writing. Both paths received the same bytes as the saved source, and the association followed each successful save.
3. Closing with an unsaved edit showed Save, Discard, and Cancel. Cancel returned to the edited document. Changing the isolated destination to read-only caused Save from the close dialog to fail while retaining the star and edit. Discard then exited. The target SHA-256 remained `7c0164e58bca84d1a0d86dad339021f1b1c179037bd1a6b91e8f3c852e396339`.
4. Reopening `new 中文.rs` showed the previously saved bytes and one native plugin. Uppercasing the first line marked it modified. An early build refused the workspace's inherited no-index attribute. After requiring the attribute to match on the staging file and original, Save from the close prompt wrote the uppercase first line and exited successfully. The replacement retained the inherited attribute.
5. In a scratch document, physical Pinyin keys opened a native candidate popup near the caret. Ctrl+S during candidate selection left the popup and the zero-byte document unchanged. Space committed `你` and added the star. Canceling Save As from the close prompt retained the edit. The toolbar Save then created the destination, cleared the star, and wrote exactly `E4 BD A0` in UTF-8. The clean window closed normally.
