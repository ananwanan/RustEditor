## M1.1 Bounded UTF-8 File Opening

The desktop opens one regular file supplied as `--open PATH`. File I/O reads at most 4 MiB plus one byte to detect overflow, even if a file grows after metadata is checked. It rejects unsupported BOMs and invalid UTF-8. Valid bytes, including LF and CRLF, enter the existing core Document unchanged. The view and plugin host share that document. The M1.1 toolbar displayed the filename and a notice that saving was unavailable.

The read uses a read-only handle before the window is created. Edits and plugin transactions affect the in-memory document. At M1.1, close confirmation protected sessions after any edit, including when undo returned to the initial text. M1.2 replaced that rule with an exact saved-content baseline.

## M1.3 Multiple Documents and Tabs

**Implemented; scoped checks recorded on 2026-11-04/05 (Asia/Shanghai).** Full M1 acceptance is still pending. These observations were collected from the M1.3 development tree based on `867db8a5c3c43b81417b6b45863852a0ce8493bb`; the observed executable hashes are recorded below. Committing the implementation does not constitute full M1 acceptance. Windows 11 Pro build 26300, Rust 1.99.1, x86_64-pc-windows-msvc, debug profile. No dependency or wire ABI changes.

Each tab owns its core document/saved snapshot, view, file association/disk baseline, save worker, status, and close state. Every worker completion carries DocumentId. Unknown/closed IDs are ignored; IDs are never reused. Saving another tab does not change the active plugin target. A requested tab close retains its worker until completion and rechecks intervening edits before closing. See the [ownership and lifetime decisions](../ARCHITECTURE.md#m13-tabs-and-active-document-routing).
