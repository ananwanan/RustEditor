# M0 Native Acceptance and GUI Decision Follow-up

Date: 2026-10-29 (Asia/Shanghai). Status: **acceptance incomplete; GUI provisional; M1 not started**.

## Cache decision and measured costs

Reviewed raw reports, each with four workloads, 19 scenarios and 30 samples per scenario (2,280 samples): [matched before](data/m0-native-render-before-2026-10-29.json), [8 MiB trial](data/m0-native-render-trial-2026-10-29.json), and [final repeat](data/m0-native-render-final-2026-10-29.json). The [complete comparison](M0_RENDER.md#2026-10-29-matched-cache-review) preserves all scenario summaries, while JSON retains every sample and outlier. Reviewed JSON copies use LF line endings; sample values are unchanged from the ignored original outputs.

Before and final have identical source fingerprints. Their differences are run variation, not a claimed production speedup. Both include the corrected cancellation setup and additional allocator atomics. They must not be treated as directly interchangeable with the 2026-10-28 harness.

The new probes measure the actual existing accounting helper and separately time destruction of a prepared painted Galley. Painting/setup is outside drop timing; selected destruction is outside accounting timing. No native input, tessellation, GPU or presentation is included. Requested allocation/live payloads are not process working set. The timer reports 100 ns increments in these samples; scheduling, allocator instrumentation and the absence of a calibrated total error bound limit interpretation, especially for near-zero probes. No statistical confidence interval is claimed from 30 samples.

| Isolated scope | Before CPU p50/p95 ms | Final CPU p50/p95 ms | Payload observation |
|---|---|---|---|
| LF base accounting, 20,972 rows | 0.070/0.135 | 0.070/0.188 | No allocation or deallocation during traversal |
| LF base plus whole painted selection accounting | 0.385/0.489 | See complete table | Walks both retained entries; no allocation |
| Long-line first-scalar selection destruction | 1.970/2.195 | 1.976/2.085 | Releases 99.841 MiB during the timed drop |
| LF whole-selection destruction | 10.505/12.063 | See complete table | Releases 101.365 MiB |
| Exact 1 MiB LF text copy | 0.253/0.303 | 0.228/0.248 | Allocates and releases 1.000 MiB |

Pinned egui 0.33.3 paints selected text through copy-on-write Galley/row glyph and mesh buffers. Selecting one scalar in the 1 MiB single line copies the entire row. Cache clearing transfers destruction of that retained copy to the IME commit/cancel event path. The isolated approximately 2 ms drop establishes a material cost, but does not explain every tail sample. Base admission traverses all LF rows, which is an additional ordinary-edit cost. No speculative rewrite of admission or event semantics was added.

The experimental alternative kept the 256 MiB combined cap but admitted a painted entry only when its incremental payload above epoch/base was at most 8 MiB. Its [exact source patch](data/m0-native-8mib-trial.patch) is retained for reproduction; it is not applied in the final source.

|---|---|---|---|---|
| LF stable whole selection | 0.462/0.580 | 48.389/52.447 | 1.009 -> 135.655 | 235.575 -> 134.211 |

| Long-line IME commit | 3.265/3.562 | 1.352/1.765 | 4.009 -> 4.009 | 232.743 -> 232.743 |
| Long-line changed preedit | 24.437/67.026 | 25.614/67.710 | 135.812 -> 135.812 | 332.457 -> 232.615 |

Decision: **reject the 8 MiB restriction and retain the existing 256 MiB combined retained-payload policy provisionally for M0**. It saves roughly 100 MiB retention, but restores large per-frame selection/preedit allocation and CPU costs. LF stable-selection peak-extra payload rises from 1.001 to 101.370 MiB; long-line repeated-preedit peak-extra rises from 1.001 to 99.847 MiB. This is a measured tradeoff, not a memory improvement accepted for the final product. The cap excludes egui's cache, frame references, transient work, allocator overhead and native/GPU memory. It is not a resident-memory bound or a large-file system.

Final stable-selection and repeated-preedit retained payloads match the before run at the reported precision; other absolute totals have small recorder/run differences. LF stable selection retains an additional 101.365 MiB over the rejected trial; long-line repeated preedit retains an additional 99.842 MiB. Final long-line IME commit is 3.360/3.920 ms internally, with a 49.425 ms worst sample. The older 14.256 ms p95 did not repeat in these runs; its original data remains intact. Final LF edit is 1.351/1.712 ms, with a 30.188 ms worst sample. Cold edit-after-idle p95 remains 26.780 ms LF and 46.938 ms long-line; changed long-line preedit p95 is 65.692 ms. These unfavorable results remain open limitations.

The first owned full-text egui lookup still copies/hashes the document each frame to keep its document/paragraph cache warm. The prior broader bypass caused recorded edit regressions. Removing this copy would require a different cache-refresh API or a broader rendering design, outside this limited investigation. Ordinary-edit accounting cost is retained and quantified rather than shifted into another frame or hidden outside timing.

The historical `ime-cancel` series did not restore focus after Escape; later samples largely measured an unfocused no-op. The corrected harness re-requests focus and asserts that every setup creates a composition and every measured commit/cancel consumes it. Historical values remain available, but their cancellation percentiles are not repeated-cancellation evidence.

Decision: retain eframe/egui 0.33.3 and the existing cache policy **provisionally**. The memory miss, mandatory physical Pinyin/DPI/font matrix and actual presentation measurements prevent a final GUI decision. No M1 feature was started. Reassess the GUI after those results, including any measured failures, rather than treating this branch's internal timings as acceptance.

The shortest remaining operator sequence is the [manual capture checklist](../../tests/perf/README.md#shortest-remaining-manual-capture): explicitly activate and verify Microsoft Pinyin, run both selection directions and focus/history/plugin cases at each native scale, verify scroll/window movement and actual monitor transitions, complete external-app/grapheme checks, then capture at least 20 warm startups and 200 ordinary LF input/display pairs with an input indicator. Report IME and long-line samples separately, retain errors/missed events, and restore original settings. Investigate the empty-buffer memory miss separately from tracing. Until those mandatory gates have actual evidence, M0 stays incomplete and M1 stays blocked.
