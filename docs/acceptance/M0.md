# M0 Technical Validation Record

Date: 2026-10-28. Status: **implementation available; acceptance incomplete**.

## Implemented

- Seven real workspace members: desktop, editor-core, plugin-api, plugin-sdk, plugin-host, text-tools cdylib, and xtask. No future placeholder crates.
- Directed byte selections, validated transactions, monotonically increasing revisions, bounded delta history, undo/redo, and atomic frame-draft commits. Unicode case expansion is one plugin transaction.
- Native eframe scratch editor; core history shortcuts, selection byte/scalar conversion, plugin command UI, system CJK font fallback, composition-time plugin suppression, close/discard confirmation, and startup without plugins.
- Header-first ABI validation, caller-owned buffers, UTF-8/boundary/size checks, revision checks, namespaced command registration, panic conversion, UI-thread checks, initialization rollback, disable-without-unload, and shutdown/destroy ordering.
- Manifest target/capability/identity validation, duplicate-ID preflight, canonical path confinement, Windows restricted DLL search, and Unix local/eager symbol resolution.
- `cargo xtask stage` and `cargo xtask verify`; baseline Ubuntu/Windows main-push/PR CI. No release automation.

The desktop and plugin host do not link text-tools. Integration tests separately build/load its cdylib and exercise `straße` → `STRASSE` in a selected range, preserving surrounding Chinese, emoji, combining characters, and CRLF. One undo restores the original text/selection; redo advances the revision.

Core tests include 2,000 deterministic randomized reference-model operations, invalid/stale edits, multibyte diff boundaries, size limits, and revision overflow. Desktop adapter tests cover one-transaction edits and rejecting an oversized replacement without losing the selected text or changing history.

Native fault fixtures cover missing entry symbols, major-version mismatches, short tables, unsupported capabilities, duplicate registrations, initialization failure, catchable panics, stale edits, wrong-thread callbacks, normal cleanup order, and failed-shutdown retention. Host callback tests cover short output tables, insufficient buffers, null/capacity errors, invalid UTF-8/ranges/identity, reentrant mutation, and host panic conversion. Manifest tests cover duplicate IDs, wrong targets, unknown capabilities, traversal, and Unix symlink escapes.

The intentional panic fixture prints a panic-hook diagnostic and returns status 5; this is expected and the test passes. The abort fixture runs only in a child process; Linux termination by SIGABRT is asserted. This demonstrates the lack of in-process crash isolation, not recovery from a native abort.

## Open Gates and Limits

- The GUI remains provisional until Windows IME/DPI checks pass. The TextEdit prototype uses Unicode scalar cursor positions; full grapheme movement/deletion requires additional work and validation.
- No earlier released SDK exists yet. Same-workspace fault fixtures and header append tests are not evidence of compatibility with an older released SDK. Freeze a separately built v1 fixture before a later host change and record that comparison.
- Ubuntu/Windows automated checks passed in the run linked above. Windows desktop UI acceptance remains pending; macOS has not been built or tested.
- No open/save, tabs, encoding conversion, recovery, large-file handling, asynchronous commands, runtime DLL replacement, hot unloading, or crash sandbox is implemented. Saving/recovery belong to later milestones.
- The 4 MiB String/draft view is a bounded prototype, not a performance claim. Undo stores at most 256 transactions / 8 MiB of removed+inserted text; oldest transactions are evicted. Undo/redo revisions never go backwards.
- All plugin commands are synchronous and must be short. Native code can still abort, deadlock, corrupt memory, or violate pointer contracts. Unknown entry state or failed cleanup intentionally retains the library and complete host callback ownership chain until process exit.
- Fonts are read from the local system and not bundled. The project license and release dependency inventory remain undecided.

M0 may be marked complete only after the outstanding native UI, compatibility, and decision gates have actual evidence. M1 has not started.
