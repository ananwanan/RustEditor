# M0 Technical Validation Record

Date: 2026-10-28. Status: **implementation available; acceptance incomplete**.

## Implemented

- Eight real workspace members: desktop, editor-core, editor-view, plugin-api, plugin-sdk, plugin-host, text-tools cdylib, and xtask. No future placeholder crates.
- Directed byte selections, validated transactions, monotonically increasing revisions, bounded delta history, undo/redo, and atomic user/IME commit transactions. Unicode case expansion is one plugin transaction.
- Native eframe scratch editor with a core-driven grapheme view; core history shortcuts, byte/scalar conversion, ordered keyboard/pointer/clipboard events, plugin command UI, bounded CJK/emoji outline font fallback, composition-time plugin suppression, close/discard confirmation, and startup without plugins. IME preedit is a transient overlay; cancellation/focus loss preserves the core and late/stale commits are ignored.
- Header-first ABI validation, caller-owned buffers, UTF-8/boundary/size checks, revision checks, namespaced command registration, panic conversion, UI-thread checks, initialization rollback, disable-without-unload, and shutdown/destroy ordering.
- Manifest target/capability/identity validation, duplicate-ID preflight, canonical path confinement, Windows restricted DLL search, and Unix local/eager symbol resolution.
- `cargo xtask stage` and `cargo xtask verify`; baseline Ubuntu/Windows main-push/PR CI. No release automation.

The desktop and plugin host do not link text-tools. Integration tests separately build/load its cdylib and exercise `straße` → `STRASSE` in a selected range, preserving surrounding Chinese, emoji, combining characters, and CRLF. One undo restores the original text/selection; redo advances the revision.

Core tests include 2,000 deterministic randomized reference-model operations, invalid/stale edits, multibyte diff boundaries, size limits, and revision overflow. The view has 16 tests: extended grapheme boundaries with full text context; horizontal/word/vertical navigation; directed Shift selections and pointer hit testing; deletion/cut/copy/undo/redo; multiple ordered events in one frame, including ordinary text before and after an IME session; 520 randomized input operations against an independent grapheme reference; joined-cluster redo carets; oversized paste and IME commit rollback; preedit/commit/cancel/focus loss/stale results; and logical caret/hit coordinates at 100%/150%/200% scale. Font validation rejects malformed fonts and missing outline glyphs before registration. These synthetic IME/scale tests do not establish native Windows behavior.

Native fault fixtures cover missing entry symbols, major-version mismatches, short tables, unsupported capabilities, duplicate registrations, initialization failure, catchable panics, stale edits, wrong-thread callbacks, normal cleanup order, and failed-shutdown retention. Host callback tests cover short output tables, insufficient buffers, null/capacity errors, invalid UTF-8/ranges/identity, reentrant mutation, and host panic conversion. Manifest tests cover duplicate IDs, wrong targets, unknown capabilities, traversal, and Unix symlink escapes.

The intentional panic fixture prints a panic-hook diagnostic and returns status 5; this is expected and the test passes. The abort fixture runs only in a child process; Linux termination by SIGABRT is asserted. This demonstrates the lack of in-process crash isolation, not recovery from a native abort.

## Open Gates and Limits

- The GUI remains provisional until Windows IME/DPI/font checks pass. The core-driven view now implements grapheme movement, deletion and selection with automated and Linux native evidence. It still uses full-document layout; virtualization, complex-script shaping, and full emoji ligatures are not implemented.
- Older SDK compatibility is explicitly not required. Host and native plugins target the current experimental SDK/ABI; rebuilding after SDK changes is acceptable. Historical SDK fixtures and compatibility shims are out of scope. ABI version, size, capability, ownership, panic and lifecycle checks remain mandatory.
- Ubuntu/Windows automated checks passed in the run linked above. Windows desktop UI acceptance remains pending; macOS has not been built or tested.
- No open/save, tabs, encoding conversion, recovery, large-file handling, asynchronous commands, runtime DLL replacement, hot unloading, or crash sandbox is implemented. Saving/recovery belong to later milestones.
- The 4 MiB String/full-galley view is a bounded prototype, not a performance claim. Undo stores at most 256 transactions / 8 MiB of removed+inserted text; oldest transactions are evicted. Undo/redo revisions never go backwards.
- All plugin commands are synchronous and must be short. Native code can still abort, deadlock, corrupt memory, or violate pointer contracts. Unknown entry state or failed cleanup intentionally retains the library and complete host callback ownership chain until process exit.
- Fonts are read from the local system and not bundled. The project license and release dependency inventory remain undecided.

M0 may be marked complete only after the outstanding native UI/font and GUI/ABI/performance decision gates have actual evidence. Older SDK compatibility is not a gate. M1 has not started.
