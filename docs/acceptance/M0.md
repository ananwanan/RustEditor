# M0 Technical Validation Record

Date: 2026-10-28. Status: **implementation available; acceptance incomplete**.

## Implemented

- Eight real workspace members: desktop, editor-core, editor-view, plugin-api, plugin-sdk, plugin-host, text-tools cdylib, and xtask. No future placeholder crates.
- Directed byte selections, validated transactions, monotonically increasing revisions, bounded delta history, undo/redo, and atomic user/IME commit transactions. Unicode case expansion is one plugin transaction.
- Native eframe scratch editor with a core-driven grapheme view; core history shortcuts, byte/scalar conversion, ordered keyboard/pointer/clipboard events, plugin command UI, bounded CJK/emoji outline font fallback, composition-time plugin suppression, close/discard confirmation, and startup without plugins. IME preedit is a transient overlay; cancellation/focus loss preserves the core and late/stale commits are ignored.
- Header-first ABI validation, caller-owned buffers, UTF-8/boundary/size checks, revision checks, namespaced command registration, panic conversion, UI-thread checks, initialization rollback, disable-without-unload, and shutdown/destroy ordering.
- Manifest target/capability/identity validation, duplicate-ID preflight, canonical path confinement, Windows restricted DLL search, and Unix local/eager symbol resolution.
- `cargo xtask stage` and `cargo xtask verify`; baseline Ubuntu/Windows main-push/PR CI. No release automation.

### Findings and chosen scope

Pinned egui/epaint 0.33.3 hashes the complete owned LayoutJob even on a cache hit, which returns a shared Galley. Multiline layouts also cache paragraphs and refresh their usage on a parent hit. The probe confirms Galley sharing on repeated requests, loss of that identity after three unused Context passes, and copy-on-write selection painting: LayoutJob stays shared, while the Galley row vector and selected row glyph/mesh buffers are copied. A one-character selection in the single long line copies its entire row, rather than only the selected glyph.

A broader prototype skipped the first layout across frames. It reduced idle copying but caused egui's previous document/paragraph entries to expire: LF alternating edit p50/p95 changed from 1.161/1.280 ms to 29.773/34.319 ms, and allocation from 4.009 to 82.790 MiB. Long-line editing similarly changed from 1.058/1.261 ms to 44.812/45.924 ms. That variant is rejected; its raw data remains available. A second measured hotspot in admission accounting was removed by replacing allocating HashSets with small array scans.

The chosen optimization preserves the first full-text egui lookup each frame, reuses unchanged layouts between ordered events, and retains one painted selection for repeated frames. Document remains authoritative. The 256 MiB conservative cache-payload limit includes the base, painted entry and tiny font-epoch probe; exceeding it declines retention and uses the existing rendering path. This cap accommodates the measured approximately 70-100 MiB base/painted objects in the 1 MiB Unicode cases; it is not a process-memory budget. Selection clearing releases the painted cache. Full text copying once each frame, costly changing long-line selections, cold layout and full-document layout remain limitations.

DocumentId/Revision and actual IME display changes invalidate cached content. Font/DPI/theme/context/font-atlas changes invalidate derived rendering; selection colors are checked independently from text color. Native preedit clearing before commit preserves the original composition range, and cancellation/late commits retain the existing transaction rules. The [architecture record](../ARCHITECTURE.md#m0-implementation-decisions) documents the pinned-egui font-epoch guard and its dependency-update requirement.

## Open Gates and Limits

- The GUI remains provisional until Windows IME/DPI/font checks pass. The core-driven view now implements grapheme movement, deletion and selection with automated and Linux native evidence. It still uses full-document layout; virtualization, complex-script shaping, and full emoji ligatures are not implemented.
- Older SDK compatibility is explicitly not required. Host and native plugins target the current experimental SDK/ABI; rebuilding after SDK changes is acceptable. Historical SDK fixtures and compatibility shims are out of scope. ABI version, size, capability, ownership, panic and lifecycle checks remain mandatory.
- Historical Ubuntu/Windows CI and the local Windows automated checks above passed. Native Windows acceptance is partial at 125% with Sogou; Microsoft Pinyin and the native 100%/150%/200% matrix remain Pending. macOS has not been built or tested.
- No open/save, tabs, encoding conversion, recovery, large-file handling, asynchronous commands, runtime DLL replacement, hot unloading, or crash sandbox is implemented. Saving/recovery belong to later milestones.
- The 4 MiB String/full-galley view is a bounded prototype, not a performance claim. Undo stores at most 256 transactions / 8 MiB of removed+inserted text; oldest transactions are evicted. Undo/redo revisions never go backwards.
- All plugin commands are synchronous and must be short. Native code can still abort, deadlock, corrupt memory, or violate pointer contracts. Unknown entry state or failed cleanup intentionally retains the library and complete host callback ownership chain until process exit.
- Fonts are read from the local system and not bundled. The project license and release dependency inventory remain undecided.

Decision: retain eframe/egui 0.33.3 provisionally for M0 validation. The fixes and dependency audit support continuing the experiment; incomplete emoji shaping, native Pinyin/DPI checks, and displayed-frame performance prevent a final GUI freeze. Retain the current experimental C ABI and its version/size/capability/ownership/lifecycle checks; no historical compatibility layer or hot unloading was added.

M0 remains **acceptance incomplete**. It may be marked complete only after the outstanding native UI/font and GUI/ABI/performance decision gates have actual evidence. Older SDK compatibility is not a gate. **M1 must not start yet** under the roadmap dependencies. No PR was created or merged on the strength of these partial results.
